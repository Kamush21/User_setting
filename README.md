# Управление пользователями и правами доступа в Linux

## Описание проекта

Проект представляет собой Bash-скрипт для автоматизации управления пользователями и группами Linux, настройки прав доступа к домашним каталогам, конфигурации `sudo` и установки веб-сервера Apache2.

Проект выполнен в учебных целях для практики системного администрирования Linux и изучения основ информационной безопасности.

## Цели проекта

* Автоматизировать создание пользователей и групп.
* Настроить разграничение доступа на основе групп.
* Ограничить доступ к домашним каталогам пользователей.
* Настроить права доступа к системным каталогам.
* Настроить правила `sudo` для определённой группы.
* Установить Apache2 и проверить состояние службы.
* Проверить корректность применённых настроек безопасности.

## Используемые технологии

* **Bash** — автоматизация настройки системы.
* **Linux** — управление пользователями, группами и разрешениями.
* `useradd`, `usermod`, `groupadd` — управление учётными записями.
* `chmod`, `chown` — настройка прав доступа и владельцев.
* `sudo`, `visudo` — управление административными привилегиями.
* **APT** — установка программного обеспечения.
* **systemd** — управление системными службами.
* **Apache2** — веб-сервер.

## Структура пользователей и групп

### Группа `default_users`

Содержит пользователя `user`.

Для этой группы предусмотрено выполнение команд через `sudo` без ввода пароля в соответствии с условием учебного задания.

### Группа `secret_users`

Содержит пользователей:

* `secret_agent`
* `secret_spy`
* `secret_boss`

Пользователи этой группы получают доступ к домашним каталогам друг друга в соответствии с настроенными правами доступа.

## Настройка прав доступа

### Домашние каталоги

Для домашних каталогов пользователей группы `secret_users` устанавливаются права `750`.

* **Владелец (`7`)** — чтение, запись и выполнение.
* **Группа (`5`)** — чтение и выполнение.
* **Остальные (`0`)** — доступ запрещён.

Такая конфигурация позволяет участникам группы просматривать содержимое каталогов и обращаться к ним, но не предоставляет группе права на изменение самих каталогов.

Доступ к отдельным файлам дополнительно зависит от их собственных разрешений.

### Каталог `/var`

В проекте используется режим `755`:

* Владелец может читать, изменять содержимое и обращаться к каталогу.
* Остальные пользователи могут читать содержимое и обращаться к каталогу.
* Запись для обычных пользователей не разрешена.

Права `777` не используются, поскольку предоставление всем локальным пользователям права на запись в системный каталог создаёт риск нарушения целостности системы.

### Настройка `sudo`

Для группы `default_users` создаётся отдельный файл конфигурации `/etc/sudoers.d/default_users`.

Перед установкой правила выполняется проверка синтаксиса с помощью `visudo`.

> **Риск безопасности:** правило `NOPASSWD: ALL` позволяет участникам группы выполнять любые команды с административными привилегиями без ввода пароля. Это условие учебного задания, а не рекомендуемая конфигурация для производственной среды.

## Установка и запуск

### Требования

* Ubuntu или Debian.
* Права суперпользователя.
* Подключение к сети для установки пакетов.
* Тестовая виртуальная машина.

### Запуск

1. Склонировать репозиторий:

   ```bash
   git clone <URL-репозитория>
   cd <название-каталога>
   ```

2. При необходимости сделать скрипт исполняемым:

   ```bash
   chmod +x setup_users.sh
   ```

3. Запустить скрипт:

   ```bash
   sudo ./setup_users.sh
   ```

Скрипт создаёт необходимые группы и пользователей, настраивает права доступа, устанавливает Apache2 и проверяет состояние службы.

## Проверка результатов

### Проверка пользователей и групп

```bash
id user
id secret_agent
id secret_spy
id secret_boss

getent group default_users
getent group secret_users
```

### Проверка прав доступа

```bash
ls -ld /home/secret_agent
ls -ld /home/secret_spy
ls -ld /home/secret_boss

stat -c '%A %a %U:%G %n' /var
```

### Проверка конфигурации `sudo`

```bash
sudo visudo -c
sudo -l -U user
```

### Проверка Apache2

```bash
systemctl is-active apache2
systemctl is-enabled apache2
systemctl status apache2 --no-pager

curl -I http://localhost
```

Ожидаемый результат: служба Apache2 запущена, настроен её автозапуск, а локальный HTTP-запрос возвращает ответ.

## Ограничения проекта

Проект предназначен для обучения и тестирования в изолированной виртуальной машине.

Перед использованием в производственной среде необходимо дополнительно проверить идемпотентность скрипта, корректность обработки уже существующих пользователей, права на файлы внутри домашних каталогов и безопасность правил `sudo`.

Для реальной инфраструктуры рекомендуется предоставлять административные привилегии только в объёме, необходимом для выполнения конкретных задач.
